# Порт на Godot

Ветка `godot-port`. Никуда не деплоится: сборка Godot пока живёт только в репозитории.

## Решения пользователя

- **Язык — C#** (Godot 4 .NET). `core` переносится на C# почти построчно, как и планировалось в `architecture.md`.
- Godot с C# не собирается под браузер, поэтому **веб-версия остаётся на TypeScript** (GitHub Pages), а Godot — отдельная сборка для компьютера.
- **Игра по сети — да, но позже.** Клиент на Godot будет играть с тем же сервером Node и с игроками из браузера. Поэтому ядро на C# с первого дня обязано давать **тот же результат, что TypeScript**, при том же сиде: тот же ГСЧ, то же округление, тот же порядок событий.
- **Первый этап — ядро боя и быстрый бой.** Потом забег, полный ИИ, сеть.
- Инструменты поставлены через winget: .NET SDK 8, Godot 4.7.2 .NET.

## Структура

```
godot/
  FantasyBrawl.sln
  Brawl.Core/         правила на C#: порт src/core. Без Godot, собирается обычным .NET SDK
  Brawl.Core.Tests/   xUnit: сверка с TypeScript по эталонам + свои тесты
    Fixtures/         эталоны, их пишет npm run parity (коммитятся)
  Game/               проект Godot: только то, что на экране. Ссылается на Brawl.Core
    content/          копия src/content, делается при сборке (не коммитится)
```

- Контент — **те же JSON** из `src/content`. Godot получает их копией при сборке (`Game.csproj`, цель `CopyContent`), экспорт несёт их внутри.
- Проверку ссылок в контенте делает TypeScript (`npm run validate-content`). C# читает каждый файл строго: неизвестное или недостающее поле — ошибка, как `.strict()` в Zod.

## Как держится совпадение с TypeScript

TypeScript — эталон. `npm run parity` (`scripts/exportParity.ts`) пишет в `godot/Brawl.Core.Tests/Fixtures` то, что говорит ядро на TS, а тесты C# сравнивают с этим свои результаты. JSON сравнивается как данные: поля объекта в любом порядке, числа по значению, `null` и отсутствующее поле равны.

Что уже сверяется:

- **ГСЧ** (mulberry32) — сырые числа, целые в диапазоне, перемешивание, в том числе для отрицательных сидов и сидов за пределами int32;
- **гексы** — линии (линия обзора), ближайшее направление, кольца;
- **контент** — весь реестр после разбора, и порядок id в нём.

Правила переноса, от которых зависит совпадение:

- `JsMath.Round` — округление как `Math.round` в JS: половина идёт к +∞. `Math.Round` в .NET округляет половину к чётному — нельзя.
- `JsMath.ToInt32` — как `x | 0`.
- ГСЧ — те же 32-битные операции (`Math.imul`, `>>>`) через `unchecked` и `uint`.
- Все числа баланса и всё, что с ними считается, — `double`, как в JS. `int` — только для счётчиков, индексов и координат гексов. Деление двух `int` в C# отбрасывает дробь, в JS нет, поэтому такого деления в портированных формулах быть не должно.
- **Порядок обхода — часть правил.** Объекты JS обходятся в порядке добавления ключей (`Object.values(heroes)`), поэтому вместо словаря — `OrderedMap`: замена ключа оставляет его место, новый ключ встаёт в конец. Ключей-чисел в игре нет, так что особый порядок JS для них не повторяется.

## Команды

```bash
npm run parity                                   # переписать эталоны после изменения core или контента
dotnet test godot/FantasyBrawl.sln               # тесты C#
dotnet build godot/Game/Game.csproj              # собрать проект Godot
```

Godot лежит в `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine.Mono_…\Godot_v4.7.2-stable_mono_win64\`. Открыть проект — `godot/Game/project.godot`.
