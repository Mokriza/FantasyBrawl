# Порт на Godot

Ветка `godot-port`. Никуда не деплоится: сборка Godot пока живёт только в репозитории.

## Решения пользователя

- **Язык — C#** (Godot 4 .NET). `core` переносится на C# почти построчно, как и планировалось в `architecture.md`.
- Godot с C# не собирается под браузер, поэтому **веб-версия остаётся на TypeScript** (GitHub Pages), а Godot — отдельная сборка для компьютера.
- **Игра по сети — да, но позже.** Клиент на Godot будет играть с тем же сервером Node и с игроками из браузера. Поэтому ядро на C# с первого дня обязано давать **тот же результат, что TypeScript**, при том же сиде: тот же ГСЧ, то же округление, тот же порядок событий.
- **Первый этап — ядро боя и быстрый бой.** Потом забег, полный ИИ, сеть.
- Инструменты поставлены через winget: .NET SDK 8, Godot 4.7.2 .NET.

## Структура

```
godot/
  FantasyBrawl.sln
  Brawl.Core/         правила на C#: порт src/core. Без Godot, собирается обычным .NET SDK
  Brawl.Core.Tests/   xUnit: сверка с TypeScript по эталонам + свои тесты
    Fixtures/         эталоны, их пишет npm run parity (коммитятся)
  Game/               проект Godot: только то, что на экране. Ссылается на Brawl.Core
    content/          копия src/content, делается при сборке (не коммитится)
```

- Контент — **те же JSON** из `src/content`. Godot получает их копией при сборке (`Game.csproj`, цель `CopyContent`), экспорт несёт их внутри.
- Проверку ссылок в контенте делает TypeScript (`npm run validate-content`). C# читает каждый файл строго: неизвестное или недостающее поле — ошибка, как `.strict()` в Zod.

## Как держится совпадение с TypeScript

TypeScript — эталон. `npm run parity` (`scripts/exportParity.ts`) пишет в `godot/Brawl.Core.Tests/Fixtures` то, что говорит ядро на TS, а тесты C# сравнивают с этим свои результаты. JSON сравнивается как данные: поля объекта в любом порядке, числа по значению, `null` и отсутствующее поле равны.

Что уже сверяется:

- **ГСЧ** (mulberry32) — сырые числа, целые в диапазоне, перемешивание, в том числе для отрицательных сидов и сидов за пределами int32;
- **гексы** — линии (линия обзора), ближайшее направление, кольца;
- **контент** — весь реестр после разбора, и порядок id в нём;
- **бои целиком** (`battles.json.gz`) — 36 боёв ИИ против ИИ: 6 быстрых (из них проверяется и сборка начального состояния из ростеров, с генерацией арены) и 30 из забегов, где есть сгенерированные герои с пассивками, перками, артефактами и все 6 модификаторов арены. Для каждого — начальное состояние, `startBattle`, затем каждое действие: события после него и состояние. Сторона A — профиль «Обычный», B — «Новичок»: его ошибки заводят в правила, которых аккуратный ИИ избегает. Покрытие: 64 из 84 способностей, 21 из 29 статусов, 21 из 26 видов событий.
- **забег** (`runs.json.gz`):
  - генерация пула героев — 50 сидов;
  - 6 забегов ИИ против ИИ целиком: каждое действие забега и состояние после него, начальное состояние каждого матча из `createRunBattle`, и что ИИ забега (пик, расстановка, замена, награда, открытие, перк) выбирает ровно те же действия, что TS;
  - 2 сценарных забега с тем, чего ИИ сам не делает: `autoPick`, отмена замены, снятие готовности, выбор после «Готов», и недопустимые действия (чужой пик, чужой гекс, «Готов» с невыбранным) — C# должен отказать в тех же местах;
  - тексты способностей (`describeAbility`) и статы на карточке для 156 героев, в том числе с перками и артефактами.

Правила переноса, от которых зависит совпадение:

- `JsMath.Round` — округление как `Math.round` в JS: половина идёт к +∞. `Math.Round` в .NET округляет половину к чётному — нельзя.
- `JsMath.ToInt32` — как `x | 0`.
- ГСЧ — те же 32-битные операции (`Math.imul`, `>>>`) через `unchecked` и `uint`.
- Все числа баланса и всё, что с ними считается, — `double`, как в JS. `int` — только для счётчиков, индексов и координат гексов. Деление двух `int` в C# отбрасывает дробь, в JS нет, поэтому такого деления в портированных формулах быть не должно.
- **Сортировка — как в V8.** `Array.prototype.sort` устойчива, строки сравниваются по кодам UTF-16 (`string.CompareOrdinal`), а `List.Sort` в .NET неустойчив. Поэтому все сортировки идут через `JsSort.Stable`: для массивов короче 64 это в точности алгоритм V8 (первый упорядоченный участок, затем бинарные вставки), для длинных — обычная устойчивая сортировка. Точная копия V8 понадобилась из-за несогласованного сравнения в очереди ходов (см. ниже); его исправили, но копию оставили: если несогласованное сравнение появится снова, ядра всё равно совпадут.
- **Равенство по ссылке.** Где TS сравнивает объекты через `===` (убрать один из двух одинаковых стаков статуса), в C# — `ReferenceEquals`: записи C# сравниваются по значению. `StatusInstance` сравнивается только по ссылке.
- **Порядок обхода — часть правил.** Объекты JS обходятся в порядке добавления ключей (`Object.values(heroes)`), поэтому вместо словаря — `OrderedMap`: замена ключа оставляет его место, новый ключ встаёт в конец. Ключей-чисел в игре нет, так что особый порядок JS для них не повторяется.
- **Степень.** Рост статов по уровням считается как `x ** steps` в JS и `Math.Pow` в C#. Обе реализации точны до последнего бита не всегда, но расхождение важно только ровно на половинке перед округлением; эталоны забегов (уровни 1–5) совпадают. Если когда-нибудь разойдутся — первым подозревать это место.

## Как запустить

```powershell
$godot = (Get-ChildItem "$env:LOCALAPPDATAMicrosoftWinGetPackages" -Recurse -Filter "Godot*_mono_win64.exe" | Select-Object -First 1).FullName
dotnet build godot/Game/Game.csproj          # собрать C# и скопировать контент
& $godot --path godot/Game                    # игра
& $godot --path godot/Game -e                 # редактор Godot (F5 — запуск)
```

Параметры после `--` — чтобы посмотреть экран без человека:

- `--screenshot=путь.png --frames=N` — через N кадров сохранить снимок окна и выйти;
- `--run` — открыть забег, а не быстрый бой; `--menu` — меню;
- `--screen=draft|placement|battle|series|upgrade|finished` — перемотать забег до этого экрана, ИИ играет за обе стороны. Уточнения: `--match=M` (номер матча), `--picks=N` (сколько пиков уже сделано), `--placed=N` (сколько героев уже стоит);
- `--expand` — на экране усиления раскрыть кандидатов на замену;
- `--click=кадр:x:y` — щелчок мышью в точке окна на этом кадре, можно несколько: так проверяются кнопки;
- `--seed=N`, `--speed=1|2|4|0`;
- `--autoplay` — за игрока тоже играет ИИ (демонстрация; с `--run` — весь забег);
- `--shots=K --every=F` — вместе со `--screenshot`: K снимков через F кадров (`путь-1.png`…), чтобы поймать эффект в движении;
- `--fxgallery` — витрина: все 3D-эффекты сразу на пустой арене, по кругу, с подписями имён из `vfx.json`. Для настройки эффектов.

Пример: `--screen=upgrade --match=3 --expand --seed=7 --screenshot=up.png --frames=30`.

Экспорт не настроен: при настройке в фильтр ресурсов надо добавить `*.json`, иначе контент не попадёт в сборку. Деплоя нет, по решению пользователя.

## Команды

```bash
npm run parity                                   # переписать эталоны после изменения core или контента
dotnet test godot/FantasyBrawl.sln               # тесты C#
dotnet build godot/Game/Game.csproj              # собрать проект Godot
```

Godot лежит в `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine.Mono_…\Godot_v4.7.2-stable_mono_win64\`. Открыть проект — `godot/Game/project.godot`.

## Найдено при переносе

- **Несогласованное сравнение в очереди ходов** (`battle/atb.ts`, `turnOrderComparator`). При равной шкале и скорости для пары «герой A и нейтральный страж N» сравнение отвечало «позже» в обе стороны, и первым ходил тот, чей id раньше по алфавиту. **Исправлено решением пользователя:** порядок сторон B → A → N, страж на ничьей уступает героям обеих сторон. Эталонный бой со стражем изменился, оба ядра его воспроизводят.
- **Подсказка к Броне в веб-версии** писала формулу «Броня / (Броня + 100)», а правило считает с `config.formulas.defenseConstant` = 70. **Исправлено:** обе версии берут число из конфига.
- **Одинокий герой ИИ пропускал каждый второй ход** — в обеих версиях: ядро закрывает ход само, а лишний `endTurn` плана оставался и закрывал следующий ход того же героя. **Исправлено** в сторе и в `BattleSession`; прогон ИИ против ИИ (`sim`, `AiMatch`) этим не страдал — он бросает план при смене хода.
