# Схема контента

Весь игровой контент — JSON в `src/content/`, валидируемый Zod-схемами из `src/core/content.ts`. Ни одна способность, предмет или перк не описывается кодом. Код знает только **атомы эффектов**, **формы наведения**, **триггеры** и **модификаторы** — из них собирается всё остальное.

## Файлы

```
src/content/
  config.json          числа баланса и правил
  classes.json         8 классов
  races.json           4 расы
  abilities/           по файлу на класс: warrior.json, mage.json ...
  passives/            по файлу на класс, по 3 пассивки
  items.json           все артефакты трёх тиров
  perks.json           перки
  arenaModifiers.json  модификаторы арены
  statuses.json        статусы: вид, стаки, какие характеристики двигают
  teams.json           готовые ростеры для «Быстрого боя» и тестов; в забеге героев делает генератор
  names.json           имена для сгенерированных героев, внутри пула не повторяются
  strings.ru.json      отображаемые строки (если не лежат в самих записях)
```

## Идентификаторы

- Формат `snake_case`, с префиксом класса у способностей и пассивок: `warrior_cleave`, `priest_passive_mercy`.
- Идентификатор никогда не меняется после появления: на него ссылаются сейвы, реплеи и тесты. Переименовать можно `name`, но не `id`.

## Способность

```json
{
  "id": "mage_fireball",
  "class": "mage",
  "name": "Огненный шар",
  "description": "Наносит {0} магического урона по зоне из 3 гексов.",
  "icon": "icons/abilities/mage_fireball.png",
  "tier": 2,
  "ap": 3,
  "cooldown": 3,
  "range": 4,
  "targets": "enemy",
  "requiresLos": true,
  "shape": { "type": "blob", "size": 3 },
  "effects": [
    { "type": "damage", "school": "magic", "scale": "magic", "k": 1.3 }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `tier` | 1–4 | Определяет цену в бюджете через `config.generation.abilityTierCost` |
| `ap` | 0–4 | Стоимость в AP |
| `cooldown` | число или `"once"` | В ходах владельца; `"once"` — раз за матч |
| `range` | число | Максимальное расстояние от героя до целевого гекса. 0 — только на себя |
| `targets` | `enemy` \| `ally` \| `self` \| `any` \| `emptyHex` | Кто может быть в центральном гексе |
| `requiresLos` | boolean | Нужна ли линия видимости до целевого гекса |
| `shape` | объект | Какие гексы затрагивает (ниже) |
| `effects` | массив атомов | Применяются по порядку к каждой цели в форме |
| `delay` | число, опционально | Эффекты сработают в начале N-го следующего хода владельца (Метеор), см. `game-rules.md` §7 |
| `ignoresZoc` | boolean, опционально | Перемещение этой способностью **не провоцирует атаку по возможности**, см. `game-rules.md` §4 |
| `description` | строка | `{0}`, `{1}` — подстановка вычисленных значений эффектов по индексу |

### Формы наведения

| `type` | Параметры | Что затрагивает |
|---|---|---|
| `single` | — | Только целевой гекс |
| `targetPlusAdjacent` | `count` | Цель + до `count` врагов рядом с ней (выбор — ближайшие по id, детерминированно) |
| `blob` | `size` | Целевой гекс и соседние. Разрешены только `1`, `3` и `7`; валидатор запрещает остальные. `3` = цель плюс два её соседа, ближайших к кастеру (тай-брейк по порядку `DIRECTIONS`); `7` = цель и все шесть соседей |
| `aura` | `radius` | Все гексы на расстоянии ≤ radius от **героя**, кроме его собственного. Раньше называлась `ring`; переименована, потому что `ring(center, radius)` в `hex.ts` — это окружность, а не круг, и одинаковые имена с разным смыслом гарантируют ошибку. У формы `targets: "self"`, `range: 0`, целевой гекс игнорируется |
| `line` | `length` | `length` гексов подряд от героя в направлении цели. Направление — ближайшее из `DIRECTIONS` к вектору `target − caster`, тай-брейк по меньшему индексу. Цель задаёт направление, а не конец линии. Линия останавливается на Скале; герои её не блокируют |
| `cone` | — | «Конус из 3 гексов» (Монах): соседний гекс в направлении цели (выбор направления — как у `line`) и два гекса на расстоянии 2 от героя, соседние с ним по бокам. Гекс прямо за передним в конус не входит. **[решение]** из плана этапа 3 |
| `chain` | `jumps`, `falloff`, `jumpRange`? | Цель, затем `jumps` прыжков. Каждый прыжок ищет ближайшую ещё не задетую цель **от предыдущей**, не дальше `jumpRange` (по умолчанию 2); линия видимости для прыжка не нужна. Ослабление накопительное: `k × (1 − falloff)^n`. Тай-брейк — меньшая дистанция, затем `heroId` |
| `allAllies` / `allEnemies` | — | Все живые союзники / враги |

Форма с фильтром: `"filter": "enemies" | "allies" | "all"` — по умолчанию совпадает с `targets`. Сам кастер обходит фильтр только у способностей с `targets: "self"`; любую другую зону, накрывшую его гекс, фильтр применяет к нему как ко всем — огненный шар вплотную не жжёт мага.

## Атомы эффектов

Закрытый список. Новый атом = новый файл в `core/battle/effects/`, запись в Zod-схеме и тесты. Без согласования с пользователем новые атомы не добавлять.

| `type` | Параметры | Что делает |
|---|---|---|
| `damage` | `school` (`physical`\|`magic`\|`pure`), `scale` (`attack`\|`magic`), `k`, `hits`?, `critBonus`?, `alwaysCrit`?, `armorPierce`?, `bonusVsLowHp`?, `perHexBonus`? | Урон по формуле из `game-rules.md`. `perHexBonus` — доля урона сверху за каждый гекс между кастером и целью («Смертельный выстрел»). `alwaysCrit` — крит без броска, в том числе при замороженных бросках ИИ |
| `heal` | `scale`, `k` \| `missingHpPct` \| `full` \| `flat` \| `pctMaxHp` | Лечение; `pctMaxHp` — процент максимального здоровья цели, без разброса |
| `status` | `status`, `turns`, `value`?, `stacks`? | Наложить статус |
| `cleanse` | `what`: `debuffs`\|`all`\|список | Снять статусы |
| `barrier` | `scale`, `k`, `turns`, `pctOfEvent`? | Барьер. `pctOfEvent` — внутри триггера: доля величины события вместо `k` × характеристика («Кубок целителя») |
| `move` | `to`: `target` \| `adjacentToTarget` | Мгновенно переместить **кастера** по кратчайшему допустимому пути. Пошаговые AP не платятся: у способности фиксированная цена. Урон Ямы начисляется только за конечный гекс. `adjacentToTarget` — свободный сосед цели, ближайший к кастеру, тай-брейк по `DIRECTIONS`; если свободного нет, способность нелегальна. Провоцирует атаку по возможности, если у способности нет `ignoresZoc` |
| `teleport` | — | Переместить кастера на целевой гекс мгновенно, сквозь препятствия и зону контроля, без атак по возможности. Атом «про землю»: один раз за применение |
| `push` | `distance`, `from`: `caster` \| `center` | Оттолкнуть цель. Направление — ближайшее из `DIRECTIONS` к вектору. Край поля, непроходимое препятствие и занятый гекс одинаково останавливают толчок без дополнительного урона. Яма при толчке наносит свой урон, но AP не трогает: это не ход цели. `root` от толчка не защищает, атаку по возможности толчок не провоцирует |
| `atb` | `delta` | Сдвиг шкалы ATB цели |
| `ap` | `delta`, `who`?: `target`\|`caster` | Изменить AP. Герою, чей сейчас ход, — сразу; любому другому — на его следующий ход (статус `apLoss`) |
| `cooldown` | `mode`: `reset`\|`double`\|`resetThis`\|`reduce`, `who`? | `reset` обнуляет все кулдауны, `double` удваивает идущие, `resetThis` обнуляет кулдаун этой способности (по умолчанию у кастера), `reduce` сокращает все идущие на 1. Потраченные «раз за бой» не трогаются |
| `summon` | `unit`, `hp`, `turns`, `attack` {`k`, `scale`, `school`, `radius`} | Призвать юнита класса `unit` (у класса `summonOnly: true`) на целевой гекс. Правила — `game-rules.md` §7 |
| `terrain` | `terrain` (`ice`\|`smoke`\|`trap`), `turns`, `onEnter`? | Временная местность на свободных гексах формы; `onEnter` — атомы капкана |
| `spread` | `status`, `radius` | Скопировать все стаки статуса с цели на каждого врага в радиусе от неё, с тем же источником и сроками («Чума») |
| `revive` | `hpPct` | Поднять павшего союзника на целевом гексе |
| `lifesteal` | `pct` | Вылечить героя на долю урона, нанесённого **предыдущим** атомом этого действия; внутри триггера — на долю урона события. Реализован на этапе 3 |
| `selfDamage` | `pctMaxHp` \| `pctCurrentHp` | Урон себе, `pure` |
| `relay` | `pct`, `school` | Только в триггере: урон цели в размере доли величины события (удара или лечения), без разброса и крита; барьер, защита и `damageTaken` действуют. «Отражённый свет» Жреца |
| `echo` | `mul` | Только в триггере `abilityUsed`: ещё раз применить эту способность с тем же прицелом, все числа × `mul`. «Эхо» Мага |

Условные атомы: любой атом может иметь `"if"`:

```json
{ "type": "status", "status": "stun", "turns": 1,
  "if": { "targetHas": "debuff" } }
```

Поддерживаемые условия: `targetHas`, `targetHpBelowPct`, `casterHpBelowPct`, `wasCrit` (относится к предыдущему атому), `killed` (предыдущий атом убил цель), `targetIsAlly` (одна зона — урон врагам и лечение союзникам, «Кара небес», «Разрыв маны»), `casterUndamagedSinceLastTurn` (с конца прошлого хода кастер не получал урона, «Убийство из тени»). Больше условий не добавлять без согласования.

Атомы, действующие на кастера (`lifesteal`, `selfDamage`, `ap`/`cooldown` с `who: caster`), выполняются и после смерти цели — иначе условие `killed` некому было бы проверять.

## Пассивки и триггеры

Пассивка — это либо постоянный модификатор, либо реакция на событие.

```json
{
  "id": "warrior_passive_hardened",
  "class": "warrior",
  "name": "Закалка",
  "description": "Каждое полученное попадание даёт +2 Брони до конца боя, максимум +12.",
  "tier": 2,
  "modifiers": [],
  "triggers": [
    { "on": "damaged", "periodic": false, "to": "self",
      "effects": [ { "type": "status", "status": "hardened", "value": 2, "turns": 99, "stacks": 6 } ] }
  ]
}
```

`tier` задаёт цену пассивки в бюджете через `config.generation.passiveTierCost` (3 / 5 / 8 / 12) — это столбец «Пассивка» таблицы тиров GDD.

Триггер: `{ on, to?, radius?, every?, oncePerMatch?, periodic?, effects }`.
- `on`: `battleStart`, `turnStart`, `turnEnd`, `damaged`, `dealtDamage`, `crit`, `kill`, `died`, `healedAlly`, `abilityUsed`, `adjacentEnemyTurnStart` (враг рядом с носителем начинает ход; `other` — этот враг, «Оковы судьбы»).
- `school` — только удары этой школы, для `damaged` и `dealtDamage` («Шипастый нагрудник»).
- `to`: `self` (по умолчанию), `other` — второй участник события, `nearestEnemy`, `enemiesAround` с `radius`.
- `every: N` — каждое N-е событие за бой; `oncePerMatch`; `periodic` — отдельно урон со временем и прямые удары.
- Семантика и порядок срабатывания — `game-rules.md` §11.

Постоянные модификаторы (`modifiers`):

```json
{ "stat": "armor", "add": 10, "scope": "adjacentAllies" }
{ "stat": "damageDealt", "mul": 0.25, "when": { "targetHpBelowPct": 40 } }
```

- `stat`: семь характеристик или боевые величины `damageDealt`, `damageTaken`, `healDone`, `critMult`, `range`, `freeSteps` (бесплатные очки ходьбы за ход, общие для всех перемещений хода), `startAtb`, `cooldownRecovery`, `apPerTurn`, `pitImmune`, `enemyAtbImmune`, `freeDisengage` (первое перемещение за ход без атак вслед), `pushImmune`, `defensePierce` (доля Брони и Сопротивления цели, которую игнорируют удары; складывается с `armorPierce` способности как `1 − (1−a)(1−b)`), `zoneSize` (зоны способностей: аура, линия, цепь +n, blob 3 → 7).
- `when.abilityTierAtLeast` — только удары способностей не ниже этого тира («Гримуар бездны»).
- `add` — плоская часть, `mul` — доля; нужна хотя бы одна.
- `scope`: `self` (по умолчанию), `adjacentAllies`, `allAllies`, `adjacentEnemies`.
- `when`: `selfHpAbovePct`, `selfHpBelowPct`, `noAdjacentAllies`, `targetHpBelowPct`, `targetHas` (статус, `debuff`, `buff`, `control`), `targetDistanceAbove`, `targetActedLast`, `targetIsolated`.
- `per`: `adjacentEnemy`, `debuffOnField` — значение умножается на счётчик.

Модификаторы вычисляются при каждом запросе итоговой характеристики и нигде не кешируются (кешируется только разбивка списка модификаторов по `stat`: она от состояния боя не зависит).

## Артефакт

```json
{
  "id": "item_butcher_blade",
  "tier": "rare",
  "name": "Клинок мясника",
  "roles": ["tank", "melee"],
  "modifiers": [
    { "stat": "attack", "add": 5 },
    { "stat": "damageDealt", "mul": 0.15, "when": { "targetHpBelowPct": 50 } }
  ],
  "triggers": []
}
```

Файл `items.json`, 28 артефактов GDD: 8 обычных, 10 редких, 10 легендарных. Запись: `{ id, name, description, tier, roles?, classes?, cost?, modifiers, triggers }`.

- `tier`: `common` \| `rare` \| `legendary`.
- `roles` и `classes` — кому артефакт подходит; отсутствие списка — всем. Классы нужны, потому что роли мало: «Посох ученика» нужен Магу, но не Охотнику, хотя оба `ranged`. Проверка — `itemFits` в `core/draft/items.ts`, одна и та же для стартового артефакта и наград.
- `cost` — цена обычного артефакта в бюджете героя (5–10, **[решение]** по силе); у обычного обязателен.
- `modifiers`, `triggers` — как у пассивки: в бою артефакт — ещё одна черта героя. Здоровье из модификаторов вшивается при сборке боя, как у перков.

## Перк

Файл `perks.json`. Та же структура, что у пассивки, плюс категория и фильтры:

```json
{ "id": "perk_quick_hands", "name": "Быстрые руки", "category": "ability",
  "description": "Выбранная способность восстанавливается на 1 ход быстрее (кулдаун не меньше 1).",
  "abilityMod": { "cooldown": -1 } }
{ "id": "perk_guardian", "name": "Страж", "category": "role", "roles": ["tank"], "unique": true,
  "description": "Соседние союзники получают на 10% меньше урона.",
  "modifiers": [ { "stat": "damageTaken", "mul": -0.1, "scope": "adjacentAllies" } ] }
```

- `category`: `stats`, `ability`, `rules`, `situational`, `role` — пять категорий GDD, только для отображения.
- `roles`, `classes` — кому перк может выпасть; без них — всем.
- `unique: true` — не предлагается герою, у товарища которого он уже есть.
- `modifiers`, `triggers` — как у пассивки.
- `abilityMod: { ap?, cooldown?, range? }` — меняет одну способность, которую игрок выбирает при взятии. Минимумы и условия — `game-rules.md` §10, «Фаза усиления».
- Модификаторы `pitImmune` (Яма без штрафа и урона) и `enemyAtbImmune` (враг не двигает по шкале) — флаги: действуют при сумме `add` больше нуля.
- Модификатор `cooldownRecovery` — ускорение кулдаунов; у атома `heal` есть `flat` — фиксированное лечение без разброса («Жнец»).

## Класс

```json
{
  "id": "hunter",
  "name": "Охотник",
  "role": "ranged",
  "primaryStat": "attack",
  "secondaryStats": ["speed", "critChance"],
  "baseAttack": "basic_ranged_physical",
  "statGrowth": { "hp": 0.12, "primary": 0.10, "secondary": 0.06 },
  "portrait": "portraits/hunter.png"
}
```

`role`: `tank` \| `melee` \| `ranged` \| `support`.

`modifiers` (необязательно) — модификаторы, которые есть у каждого героя класса, как у пассивки, которую никто не выбирает: тот же формат `{ stat, add?, mul?, when?, scope? }`, без триггеров. В бою класс — первая черта героя (`traitsOf`: класс, пассивка, раса, перки, артефакт). С ними обязателен `traitDescription` — текст для игрока, он виден на карточке драфта и в подсказке карточки героя. Этап 5: танкам и ближнему бою дан бесплатный первый шаг за ход (`{ "stat": "freeSteps", "add": 1 }`).

`summonOnly: true` — класс только для призывов (бес Чернокнижника): не генерируется, не попадает в пул драфта, правила пулов к нему не применяются. Валидатор требует, чтобы атом `summon` ссылался только на такие классы.

## Раса

```json
{ "id": "dwarf", "name": "Дворф", "description": "+12% Здоровья, +6 Брони, −2 Скорости.",
  "modifiers": [ { "stat": "maxHp", "mulBase": 0.12 }, { "stat": "armor", "add": 6 }, { "stat": "speed", "add": -2 } ] }
```

Раса: `{ id, name, description, modifiers }`, модификатор — `{ stat, add?, mulBase?, mul? }`.
- На одной из семи характеристик модификатор срабатывает **один раз, при генерации** героя: `mulBase` масштабирует сгенерированное число, `add` прибавляется сверху. Эти бонусы уже лежат в характеристиках героя и в бою второй раз не применяются.
- На боевой величине (`startAtb`, `critMult`, `damageDealt` и прочие из списка модификаторов) — действует в бою, как модификатор пассивки: `add` прибавляется, `mul` — доля, как у пассивок («+10% к урону» Орка — `{ "stat": "damageDealt", "mul": 0.1 }`). `mulBase` на боевой величине не действует.
- Бонусы расы должны быть полезны **любому** классу (решение пользователя): никаких «+Атаки» или «+дальности», которые пригодятся только части классов.
- Порядок и округление — `game-rules.md` §10, шаг 7.

## Модификатор арены

Файл `arenaModifiers.json`: `{ id, name, description, rules }`, где `rules` — объединение по полю `kind`:

| `kind` | Параметры | Модификатор |
|---|---|---|
| `shrink` | `everyRounds` (4), `ringDamage` (15) | Сужающаяся арена |
| `manaStorm` | `cooldownBonus` (1), `dotMultiplier` (2) | Шторм маны |
| `bloodHarvest` | `healMultiplier` (0.5), `killAtb` (30) | Кровавая жатва |
| `fog` | `sightRange` (3) | Густой туман |
| `powerPoint` | `damageBonus` (0.2), `holdRounds` (5) | Точка силы |
| `guardian` | `classId` (класс с `summonOnly`), `maxHp`, `attack`, `armor`, `resist`, `speed`, `k` | Древний страж |

Каждый `kind` понимает одна функция в `core/arena/modifiers.ts`; бой спрашивает там, а не читает id сам. Модификаторы — единственное место, где новый контент требует нового кода, поэтому их мало. Какие матчи идут с модификатором — `config.run.modifierMatches`.

## Правила валидации пулов

`npm run validate-content` обязан проверять не только схему, но и эти инварианты. Нарушение — ошибка сборки.

1. В пуле каждого класса ровно 10 активных способностей и не меньше 3 пассивок. **Пока предупреждение, не ошибка:** пулы этапа 1 намеренно неполные, потому что часть способностей требует атомов этапа 3. Поднять до ошибки на этапе 3, TODO стоит в `scripts/validateContent.ts`.
2. Распределение тиров в пуле: ровно 2 тира I, ровно 2 тира IV, остальные 6 — тиры II и III. **Тоже предупреждение**, по той же причине, и проверяется только на полном пуле. Отдельно отмечу: в `docs/GAMEDESIGN.md` у Воина по одной способности тира I вместо двух, так что даже полный пул Воина правило не пройдёт — это вопрос к дизайну контента. Пул Паладина переделан (см. ниже) и правило проходит.
3. Сумма цен `generation.startingAbilities` (2) самых дешёвых способностей класса тиров I–III ≤ нижней границы `config.generation.abilityBudget` (8). Иначе генерация может не собрать героя.
4. Цены тиров в `config.generation.abilityTierCost` возрастают строго. Запрет двух способностей тира IV у одного героя обеспечивает **генератор** явной проверкой, а не бюджет: при ценах 4/7/11/16 два ультимейта и тир I стоят 36 и в бюджет 40 влезают.
5. Способности с `stun`, `silence` или `root` имеют `cooldown >= 4` или `"once"`. Правило проверяется только для способностей, бьющих по врагу (`targets: enemy` или `any`): самообездвиживание вроде «Стойки» Воина — это цена способности, а не контроль, от которого правило защищает.
6. Классы с ролью `ranged` имеют в пуле не больше 2 способностей с атомом `move` или `teleport` на себя.
7. У каждого `id` есть `name` и `description`, у каждой способности — `icon` (может указывать на плейсхолдер).
8. Все `{N}` в `description` соответствуют существующему индексу эффекта.
9. Все ссылки (`baseAttack`, `status`, `unit`, `terrain`) указывают на существующие записи. Статусы для этого лежат в `statuses.json` как данные: сверяться с константным списком в коде означало бы нарушить правило «контент — данные, а не код».
10. Ростеры в `teams.json` ссылаются на существующие классы и способности, способность принадлежит классу героя, и у героя не больше одной способности тира IV.
11. У каждого класса не меньше 3 активных способностей: генератор выдаёт герою три. Сейчас это впритык выполняет Чернокнижник (3 способности), поэтому все Чернокнижники в пуле получают один и тот же набор.
12. В `names.json` не меньше имён, чем `config.draft.poolSize`, и без повторов (повторы ловит ещё схема).
13. *(снято на этапе 3)* Раньше проверялось, что 40% бюджета характеристик влезают в диапазон главной. С дешёвыми пассивками это невыполнимо у самых «богатых» героев; генератор тогда ставит главную в потолок, см. `game-rules.md` §10.
14. Каждая сторона ставит столько героев, сколько выбирает: число `A` и `B` в `config.draft.placementOrder` совпадает с `config.draft.order`, а пиков не больше, чем героев в пуле.
15. Число столбцов арены нечётное (генератору нужен ничей центральный столбец), стартовые столбцы лежат на поле, `arena.obstacles.max` не больше половины свободных гексов, возвышенностей не больше двух.
16. `draft.maxSameClass × число классов ≥ draft.poolSize`: иначе пул нельзя набрать, не нарушив лимит.
17. У каждого класса пассивок не меньше, чем `run.unlockChoices`.
18. Каждому классу подходит хотя бы один артефакт каждого тира: иначе генерации нечего выдать, а награде нечего предложить.
20. У класса с `modifiers` есть `traitDescription`: правило, о котором игрок не может прочитать, — скрытое правило.
19. Матчи из `run.modifierMatches` лежат в 1…`run.maxMatches`, и при непустом списке есть хотя бы один модификатор арены.

Все числа — в `config.json`, смысл — в `game-rules.md` §10.

|---|---|

| `generation.abilityTierCost` | Цена способности по тиру: 4 / 7 / 11 / 16 |
| `generation.abilityBudget` | Диапазон доли на стартовые способности, `[8, 22]` |

### Статусы как данные

Запись статуса описывает `kind` (`debuff` / `buff` / `special`), `hardControl`, `maxStacks`, `valueKind` (`flat` / `fraction` / `none`) и какие характеристики он двигает. Знак живёт в записи, а не в контенте: дебафф вычитает, бафф прибавляет, поэтому в способности всегда стоит положительная величина. Итог считается как `(база + Σ плоских) × Π (1 + долевых)`.

Таблица в `game-rules.md` §7 перечисляет только дебаффы, но без положительных статусов не собираются «Стойка», «Каменная кожа» и «Благословение», а пример пассивки выше уже ссылается на `armorUp`. Поэтому заведены `fortify` (доля брони и сопротивления), `stoneskin` (плоская броня и сопротивление) и `empower` (доля атаки и магии).

### Флаги статусов

Необязательные поля записи статуса, которыми собраны статусы этапа 3:

| Флаг | Что делает |
|---|---|
| `battleStat`, `battleSign` | Статус двигает боевую величину модификатора (`damageTaken`, `range`, `apPerTurn`…). Знак — по `kind`, `battleSign` его переопределяет («Охота» — дебафф, повышающий получаемый урон) |
| `controlImmune` | Не ложатся `stun`, `root`, `silence` |
| `ignoresLos` | Способности носителя не требуют линии видимости |
| `untargetable` | Враги не могут выбрать носителя целью — ни вручную, ни автоматическим выбором; атак по возможности он не провоцирует; площадные удары его накрывают. Проверка — `hiddenFrom` в `core/battle/statuses.ts`, см. `game-rules.md` §7 |
| `invulnerable` | Любой удар по носителю ничего не делает |
| `deathWard` | Смертельный удар оставляет 1 здоровья, статус снимается |
| `drainPctMaxHp` | Доля максимального здоровья, теряемая в начале каждого хода |
| `breaksOnDamageDealt` | Статус спадает, как только носитель нанёс удар атомом `damage` (не тиком) |
| `critsWhileOn` | Каждый удар носителя, пока статус на нём, — крит |
| `reflectPct` | Первый вражеский удар делится: эта доля уходит атакующему чистым уроном, остальное — носителю; статус спадает |
| `apOnKill` | Убийство носителем в его ход даёт столько AP |
| `blocksStatus` | Первый раз, когда на носителя ложится этот статус, он не ложится, а этот статус спадает («Броня стража») |
| `reviveAtPct` | Как `deathWard`, но оставляет эту долю максимального здоровья («Сердце феникса») |
| `atbOnEnemyAction` | `{ radius, delta }`: после каждого действия врага, закончившегося в пределах `radius`, носитель получает `delta` ATB |

## Как добавить способность

1. Прочитать пул класса и убедиться, что после добавления правила 1–6 выполняются.
2. Собрать её из существующих атомов, форм и условий. Если не собирается — остановиться и обсудить с пользователем.
3. Добавить запись в `abilities/<class>.json`.
4. `npm run validate-content`.
5. Написать сценарный тест в `core/battle/__tests__/abilities/`: фиксированный сид, фиксированное поле, одно применение, проверка событий.
6. Прогнать `npm run sim -- --matches 1000` и посмотреть, не изменился ли винрейт класса больше чем на 5 процентных пунктов.
