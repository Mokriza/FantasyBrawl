# Онлайн PvP через лобби

Этап 5б, сделан. Часть 1 — `src/net`, часть 2 — `src/server`, часть 3 — клиент (`src/ui/net` и сетевой режим стора), часть 4 — размещение. Сервис на Render пользователь поднимает сам по инструкции в README.

## Решения пользователя

- Игрок против игрока через лобби.
- Транспорт — **свой сервер Node + WebSocket**. Сервер запускает тот же `core` и проверяет каждое действие, как требуют GDD и `architecture.md`. Клиенту не доверяем.
- Таймеры: пик в драфте 60 с (GDD), расстановка 30 с на героя, фаза усиления 120 с, ход в бою 30 с. По истечении сервер сам делает ход за игрока. Числа — `config.online`.
- Выборы соперника в фазе усиления видны сразу, как в игре с ИИ.
- В первой версии — лобби по коду, забег, переподключение и чат комнаты. Реванша и зрителей нет.
- Хостинг сервера — Render. Клиент остаётся на GitHub Pages.

## Как это устроено

```
GitHub Pages (клиент)  ── wss:// ──  сервер Node (src/server)
        │                                   │
   ui: шлёт намерение,                 net + core: единственный судья,
   прогоняет принятые записи           пишет лог комнаты и рассылает его
```

- **Сервер авторитетен.** Клиент шлёт только намерение — запись лога: `RunAction` или `Action`. Сервер проверяет, что запись от нужной стороны (`actorOf`) и законна (`isLegalEntry`: для боя — `legalActions`, для забега — пробное применение). Затем применяет её и рассылает обоим.
- **Синхронизация — лог записей.** Игра = сид + лог. `applyEntry` из `src/net/log.ts` одна для сервера и клиента, поэтому расхождений нет. Два шага выводятся из лога, а не пишутся в него: начало боя (забег вошёл в фазу боя) и отчёт о матче `matchEnded` (у боя этого матча есть итог).
- **Проверка версии.** В `hello` клиент сообщает `PROTOCOL_VERSION` и хеш контента (`contentHash`, FNV-1a над реестром). Не совпало — отказ `version`: при разном контенте один лог дал бы разные игры.
- **Случайность.** Сид забега, коды комнат и токены бросает сервер (`crypto`). Это вне `core`.
- **Скрытой информации в правилах нет** (GDD), поэтому оба клиента получают одно и то же.

## Лобби

- «Создать игру» → комната с кодом из 5 символов без похожих знаков (нет 0/O, 1/I). Создатель видит код, может скопировать его.
- «Войти» по коду → второе место. Третьему — «в комнате уже два игрока».
- Оба нажимают «Готов» → старт. Кто драфтует первым, решает бросок `createRun`; создатель комнаты играет выпавшую «игроку» сторону.
- Имя без аккаунта: поле ввода, хранится в `localStorage`. Смена имени до входа в комнату отправляет `hello` заново.
- Публичного списка комнат нет, только код.

## Протокол (JSON, схемы Zod — `src/net/protocol.ts`)

| Клиент → сервер | Сервер → клиент |
|---|---|
| `hello { version, contentHash, name, token? }` | `welcome { playerId, token }` |
| `createRoom` | `room { code, seats, you, started }` — `you` = номер своего места |
| `joinRoom { code }` | `started { seed, you: Side, names }` |
| `lobbyReady { ready }` | `applied { seq, entry }` — принятая запись лога |
| `act { seq, entry }` | `rejected { seq, reason }` |
| `continue` — «Далее» после матча | `snapshot { seed, you, names, log, chat }` — при возвращении |
| `chat { text }` | `timer { deadline, serverNow, side }` — `side: null` = часы обеих сторон |
| `leave` | `chat { line }`, `continueWaiting { sides }`, `opponentLeft { returnBy, serverNow }`, `opponentBack`, `ended { winner, reason: 'finished' \| 'forfeit' }`, `error { reason }` |

- `seq` — длина лога, на которую рассчитано действие. Устаревшее отклоняется (`stale`).
- Записи `matchEnded` в логе нет (выводится), `nextMatch` пишет сервер, когда оба нажали «Далее» или вышло время, `autoPick` и прочие автоходы — по таймеру.

## Сервер (`src/server`)

- `rooms.ts` — лобби без сокетов: `receive(connId, raw)` и `send` снаружи, время, случайность и таймеры передаются параметрами. Поэтому тесты играют целые забеги без сети и без настоящих часов.
- `auto.ts` — часы (`clockOf`) и автоход по истечении (`timeoutEntry`): случайный пик, первый свободный гекс, в фазе усиления первые варианты и «готов», в бою конец хода, после матча `nextMatch`. Часы перезапускаются только при смене ключа: новый пик, новая постановка, новый ход; в фазе усиления — одни на всю фазу, выборы внутри их не перезапускают.
- `main.ts` — HTTP (`/health`) и `ws` на одном порту `PORT`, проверка `Origin` по `ALLOWED_ORIGINS`, сообщение до 8 КБ.
- Защита: схемы Zod, не больше `messagesPerSecond` сообщений в секунду, до `maxRooms` комнат, пустая комната удаляется через `emptyRoomMinutes`, чат — до `chatMax` символов не чаще раза в `chatEverySeconds`, хранится `chatKeep` строк.
- Обрыв связи: место держится `reconnectSeconds` (120 с), соперник получает `opponentLeft`. Вход с тем же `token` → `snapshot`, сопернику `opponentBack`. Не вернулся — `ended { reason: 'forfeit' }`. `leave` из начатой игры — поражение сразу. Часы во время обрыва идут, автоходы не дают игре встать.
- Состояние только в памяти. Перезапуск сервера (например, засыпание на бесплатном Render) теряет комнаты: клиент видит «Сервер перезапустился, и игра потеряна».

## Клиент (`src/ui`)

- `ui/net/client.ts` — сокет: разбор сообщений, переподключение с паузами 0,5–8 с. Протокола не знает.
- Стор, режим `'online'`:
  - ход игрока не применяется, а уходит в очередь отправки. Записи уходят по одной с текущим `seq`; на `stale` запись отправляется снова, если ещё законна;
  - каждая `applied` проходит через `applyEntry`; события боя идут в ту же очередь проигрывания, что и против ИИ. Конец матча показывается, когда доиграли события;
  - ИИ, локальный таймер пика и автоход интерфейса выключены, `playerSide` = `you` от сервера;
  - токен — в `sessionStorage`: две вкладки одного браузера — два игрока, перезагрузка вкладки возвращает на место. «В меню» забывает токен.
- Экран «Игра по сети» (`screens/OnlineScreen.tsx`): имя, «Создать игру», вход по коду, места с отметкой «готов», «Сервер просыпается…», если подключения нет дольше 3 с.
- Поверх экранов забега (`panels/Online.tsx`): часы сервера в верхней полосе («Ваше время», «Время соперника», «Время на выбор»), полоса «Соединение потеряно…» / «Соперник отключился, ждём N с», чат с числом новых сообщений, экран победы или поражения по неявке.
- Фаза усиления: «Готов» / «Отменить готовность» и «Соперник готов» / «Соперник выбирает…». После матча «Далее» ждёт соперника.
- Выход в меню из идущей игры спрашивает подтверждение: это поражение.

## Размещение

- Адрес сервера — `VITE_SERVER_URL` при сборке. Пустой — пункт «Игра по сети» скрыт, сайт работает как раньше. Локально — `.env.development` с `ws://localhost:8787`.
- Сервер — `render.yaml` (Blueprint Render): `npm ci --include=dev` (tsx — dev-зависимость), `npm run server`, проверка `/health`, `ALLOWED_ORIGINS` вводится при создании. Сборка Pages берёт `VITE_SERVER_URL` из переменной репозитория `vars.VITE_SERVER_URL` (`deploy.yml`).
- На бесплатном Render сервис засыпает без трафика; первое подключение ждёт до минуты — клиент показывает «сервер просыпается».
