# Интерфейс и отрисовка

`src/ui/` — единственное место, где существует браузер. Интерфейс ничего не решает: он показывает состояние, собирает намерения игрока в `Action` и проигрывает события.

## Разделение

| Что | Чем | Почему |
|---|---|---|
| Поле, герои, подсветки, эффекты | PixiJS | Много объектов, анимации, 60 fps |
| Панели, карточки, очередь ATB, лог, меню, драфт | React | Формы и текст, частые изменения макета |
| Связь между ними | Один стор | Одна правда о текущем состоянии |

Pixi-приложение создаётся **императивно** внутри React-компонента `BoardCanvas` через `ref` и `useEffect`, с явным `destroy()` при размонтировании. Не использовать React-обёртки над Pixi без согласования — они добавляют ещё один слой версий и отладки.

## Стор

Небольшой стор (Zustand или свой на `useSyncExternalStore` — согласовать при старте), в котором лежат:

```ts
interface UiStore {
  mode: 'menu' | 'run' | 'quick';
  run: RunState | null;          // из core; null в меню и в быстром бою
  battle: BattleState | null;    // из core; во время расстановки — превью линии, которое никто не играет
  pendingEvents: BattleEvent[];  // очередь на анимацию
  animating: boolean;
  selection: { abilityId: AbilityId | null; hoverHex: Hex | null };
  dispatch(action: Action): void; // единственный путь изменить battle
}
```

- `dispatch` вызывает `applyAction` из `core`, кладёт новое состояние и события в стор.
- Пока `animating === true`, ввод игрока блокируется.
- Стор не содержит игровой логики. Вопрос «можно ли сюда походить» решает `legalActions`, а не стор.

## Анимация событий

Интерфейс анимирует **события**, а не разницу состояний.

```
dispatch(action)
  → core возвращает { state, events }
  → state сохраняется сразу, но «отображаемое состояние» остаётся старым
  → события проигрываются по очереди, каждое двигает отображаемое состояние
  → после последнего события отображаемое == реальное, ввод разблокирован
```

- Каждому типу события — одна функция анимации в `ui/board/animations/`, возвращающая `Promise`.
- Длительности — в `ui/config.ts`, с глобальным множителем скорости (×1, ×2, ×4) и режимом «без анимаций» для отладки.
- Если тип события не имеет анимации — применить мгновенно и написать `console.warn` в dev-режиме.
- Ходы ИИ проигрываются тем же механизмом, по одному действию.

## Экраны

1. **Главное меню** — новый забег, быстрый бой на ростерах `teams.json`, сид (поле для ввода, по умолчанию случайный). Выбор сложности ИИ появится на этапе 5, когда профили кроме `normal` будут настроены.
2. **Драфт** — пул карточек, две колонки команд, таймер, порядок пиков с отметкой текущего. Карточка показывает всё сразу: класс и роль, все характеристики с полоской «насколько вложено в диапазон», раскладку бюджета, три способности с текстом, где числа подставлены для этого героя.
3. **Расстановка** — поле с ареной матча, свои свободные гексы подсвечены ярко, зона противника — бледно. Герой выбирается в списке слева и ставится кликом по гексу (перетаскивание не сделано). Стороны ставят по одному по очереди.
4. **Бой** — поле в центре, очередь ATB сверху, карточка активного героя с кнопками способностей снизу, лог справа. Сверху — номер матча, счёт серии и уровень.
5. **Фаза усиления** — по каждому герою игрока: что дал новый уровень, «Открытие» (после 1-го матча — две пассивки на выбор, после 2-го — две способности тира IV с числами) и три карточки перков; перк на способность спрашивает, на какую. Справа — выборы противника (они открыты). Кнопка «К расстановке» активна, когда выбрано у всех. Предмет и замена героя — этап 4.
6. **Итог матча / итог забега.**

Переключение экранов — по состоянию `run.phase` из `core`. Не заводить отдельный роутер. Ход соперника в драфте и расстановке идёт через те же действия забега, что и ход игрока, с короткой паузой (`ui/config.ts`, `OPPONENT_PICK_MS`), чтобы выбор было видно.

Цвета сторон — относительные: команда игрока всегда синяя, соперник всегда красный, независимо от того, досталась игроку сторона A или B (`sideColor(side, playerSide)` в `ui/theme.ts`, класс `.player-B` в CSS меняет местами переменные).

## Бой: взаимодействие

- **Наведение на гекс:** если способность не выбрана — подсветка пути и стоимости в AP. Если выбрана — подсветка зоны и превью урона.
- **Превью урона:** диапазон `min–max` и шанс крита, посчитанные функцией `previewAbility` из `core`. Интерфейс не считает урон сам.
- **Клик:** собрать `Action`, проверить наличие в `legalActions`, вызвать `dispatch`.
- **Недоступное действие** (нет AP, кулдаун, нет обзора) — кнопка неактивна, подсказка объясняет причину. Причину возвращает `core`, а не выводит интерфейс.
- **Горячие клавиши:** `1`–`3` — способности, `Q` — базовая атака, `Space` — конец хода, `Esc` — отмена выбора.
- **Поле.** Местность рисуется векторно в `board/render.ts`: Скала, Заросли, Яма, а на время — Лёд (кристалл), Дым (серые клубы) и Капкан (челюсти). Жёлтый пунктир по краю — «через гекс не видно», он берётся из `blocksLos` ядра, а не из списка типов. Зона отложенной способности («Метеор») подсвечена оранжевым до срабатывания. Призыв — фигура на диске поменьше; в боковых колонках его нет, там только три героя.
- **Статусы на карточке** сгруппированы: один значок на статус, `×N` для стаков, оставшиеся ходы — наибольшие из стаков. Длительность больше `battle.maxRounds` означает «до конца боя» и числом не показывается.

## Очередь ATB

- Показывает 6 следующих ходов по прогнозу из `core` (`predictTurnOrder`).
- Пересчитывается после каждого события, не только после действия.
- При наведении на способность, двигающую ATB, показывает очередь **после** её применения — это главный инструмент понимания инициативы.

## Ассеты

- Никаких путей к картинкам в коде. Пути — в JSON контента (`icon`, `portrait`) и в `ui/assets/manifest.json` для тайлов и эффектов. Пути пишутся от корня сайта (`/assets/...`); перед использованием их пропускают через `assetUrl` из `ui/assets/url.ts`, который добавляет базовый путь Vite. На GitHub Pages игра живёт в `/FantasyBrawl/`, и без этого картинки не загрузятся.
- Любой отсутствующий ассет подменяется плейсхолдером: цветной круг класса с буквой, серый гекс для тайла. Игра никогда не падает из-за отсутствующей картинки.
- Цвета классов и сторон — в `ui/theme.ts`.
- Источники бесплатных ассетов и их лицензии записываются в `ASSETS.md` в корне: что, откуда, лицензия, нужна ли атрибуция. Ассет без записанной лицензии не коммитить.
- Предпочтительные источники: Kenney (CC0), game-icons.net (CC BY 3.0, требует атрибуции), OpenGameArt и itch.io (лицензия у каждого пака своя — проверять).

## Строки

Все отображаемые строки — на русском. Названия и описания контента — в JSON. Строки интерфейса — в `ui/strings.ru.ts`. Не хардкодить текст в JSX, чтобы добавление английского языка было правкой одного файла.

## Чего не делать

- Не вычислять в `ui` ничего, что влияет на исход: урон, достижимость, линию видимости, очередь.
- Не хранить копию `BattleState` в состоянии React-компонентов.
- Не добавлять звуки, пока `roadmap.md` не дошёл до этапа полировки. Проигрывание событий по очереди перенесено из этапа 6 в этап 1 по просьбе пользователя: без него бой читался как телепортация фигур. Чистая часть проигрывания живёт в `ui/playback.ts` и покрыта тестами.
