# CLAUDE.md

Браузерный тактический арена-баттлер 3v3 в фэнтези-сеттинге. Драфт команды из пула сгенерированных героев, пошаговый бой на гексах 9×9 с ATB-инициативой и очками действия, серия матчей до трёх побед. Сейчас — игрок против ИИ. Позже — онлайн PvP и порт на Godot.

Проект учебный. Приоритеты по убыванию: **корректность правил → читаемость кода → скорость итерации → производительность → красота.**

## Стек

TypeScript (strict) · Vite · React (панели интерфейса) · PixiJS (игровое поле) · Zod (валидация контента) · Vitest (тесты) · tsx (запуск симуляций в Node).

## Команды

```bash
npm install          # установка
npm run dev          # dev-сервер Vite
npm run build        # прод-сборка
npm run typecheck    # tsc --noEmit
npm run lint         # ESLint, включая запрет импортов в core
npm test             # Vitest, однократно
npm run test:watch   # Vitest в watch-режиме
npm run sim -- --matches 1000 --seed 42   # балансная симуляция в Node
npm run validate-content                  # проверить все JSON контента по схемам
```

Перед тем как сказать «готово»: `npm run typecheck && npm run lint && npm test`. Всё зелёное — иначе задача не закончена.

## Структура

```
src/
  core/      чистые правила игры. Без DOM, React, Pixi, Math.random, Date
  content/   JSON: классы, способности, предметы, перки, расы, модификаторы, config
  ai/        utility AI для боя и драфта. Зависит только от core
  sim/       headless-прогон матчей для баланса. Запускается в Node
  ui/        React + Pixi. Единственное место, где есть браузер
docs/
  GAMEDESIGN.md  геймдизайн-документ (экспорт из Word). Намерение дизайнера
  ai/        инструкции для ИИ-разработчика (этот набор)
```

## Жёсткие правила

Нарушение любого из них — баг, даже если игра работает.

1. **`src/core` не импортирует ничего из `ui`, `react`, `pixi.js`, DOM.** Ядро должно запускаться в Node. ESLint это проверяет — не отключай правило.
2. **Никакого `Math.random()` и `Date.now()` в `core`, `ai`, `sim`.** Вся случайность — через сидированный `Rng`, который живёт в состоянии.
3. **Состояние неизменяемое.** `applyAction(state, action)` возвращает новое состояние и не мутирует аргумент.
4. **Один источник правды о допустимых действиях — `legalActions(state)`.** Интерфейс и ИИ используют её, а не свою копию логики.
5. **Контент — данные, а не код.** Новая способность = новая запись в JSON из существующих атомов эффектов. Новый атом — только если без него никак, и с тестом.
6. **Числа баланса живут в `src/content/config.json`**, а не в коде. В коде — только ссылки на конфиг.
7. **Не выдумывай правила.** Если поведение не описано в `docs/ai/game-rules.md` или `docs/GAMEDESIGN.md` — остановись и спроси. Не угадывай молча.

## Как работать

- **Маленькими шагами.** Одна задача — одна проверяемая вещь. Не пиши пять систем за один заход.
- **Сначала тест правила, потом правило.** Для `core` это обязательно, для `ui` — нет.
- **Не расширяй скоуп.** Если задача — «добавить Яд», не переписывай систему статусов «заодно». Заметил проблему — упомяни в ответе, не чини без спроса.
- **Сверяйся с roadmap.** Не реализуй то, что там помечено как отложенное (онлайн, Godot, анимации), пока пользователь не попросит.
- **Заканчивай отчётом:** что сделано, как проверено, что осталось неясным.
- **Обновляй документацию**, если изменил правило, схему или структуру. Устаревший документ хуже отсутствующего.
